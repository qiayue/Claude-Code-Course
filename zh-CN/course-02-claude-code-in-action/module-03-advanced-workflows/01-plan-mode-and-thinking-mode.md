## 核心概念

对于简单的任务，Claude Code 可以直接开始执行。但面对复杂任务时，你可能希望 Claude 先**思考和规划**，再动手修改代码。Claude Code 提供了两种特殊模式来应对不同类型的复杂性。

## 两种模式概览

| 特性 | 计划模式（Plan Mode） | 思考模式（Thinking Mode） |
|------|----------------------|------------------------|
| **侧重点** | 广度 | 深度 |
| **适用场景** | 多文件、多功能的任务 | 逻辑密集、边界情况多的任务 |
| **输出** | 步骤化的执行计划 | 深度推理分析 |
| **触发方式** | 快捷键或命令 | 关键词触发 |

## 计划模式（Plan Mode）

### 什么是计划模式？

计划模式让 Claude Code 在修改任何代码之前，先制定一个详细的执行计划。你可以审查、修改或批准这个计划，然后 Claude 再按计划执行。

### 何时使用

- **大规模重构**：需要修改多个文件的结构性变更
- **新功能开发**：需要创建多个新文件和修改多处的功能
- **架构变更**：影响面较广的技术决策
- **不确定最佳方案时**：想先看看 Claude 的建议再决定

### 使用方法

通过快捷键切换到计划模式：

```
按 Shift+Tab 切换到 Plan 模式
```

或者在提示中明确要求：

```
> 帮我规划一下如何将用户认证从 JWT 迁移到 Session-based。先制定计划，不要修改代码。
```

### 计划模式的工作流程

```
1. 你描述任务
       ↓
2. Claude 分析代码库，制定执行计划
       ↓
3. Claude 展示计划：
   - 需要修改的文件列表
   - 每个文件的具体变更
   - 执行顺序和依赖关系
   - 潜在风险和注意事项
       ↓
4. 你审查计划：
   - 批准并执行
   - 要求修改某些步骤
   - 取消并重新规划
       ↓
5. Claude 按计划逐步执行
```

### 示例

```
> [Plan Mode] 添加一个完整的用户权限系统，支持 RBAC

Claude 的计划输出：

## 执行计划

### 第 1 步：创建数据模型
- 创建 `src/models/role.ts` — 角色模型
- 创建 `src/models/permission.ts` — 权限模型
- 修改 `src/models/user.ts` — 添加角色关联

### 第 2 步：实现权限中间件
- 创建 `src/middleware/auth.ts` — 权限检查中间件
- 创建 `src/middleware/rbac.ts` — 角色检查中间件

### 第 3 步：更新 API 路由
- 修改 `src/routes/admin.ts` — 添加管理员权限要求
- 修改 `src/routes/users.ts` — 添加用户权限检查

### 第 4 步：创建管理界面
- 创建 `src/pages/admin/roles.tsx` — 角色管理页面
- 创建 `src/pages/admin/permissions.tsx` — 权限管理页面

### 第 5 步：编写测试
- 创建 `tests/rbac.test.ts` — 权限系统测试

### 潜在风险
- 现有的 admin 路由可能需要更新认证逻辑
- 需要数据库迁移来添加新表
```

## 思考模式（Thinking Mode）

### 什么是思考模式？

思考模式让 Claude 在回复之前进行更深入的内部推理。这对于需要仔细思考的复杂问题特别有效。

### 何时使用

- **复杂的 Bug 调试**：错误原因不明显，需要深入分析
- **算法设计**：需要考虑多种边界情况
- **安全分析**：需要发现潜在的安全漏洞
- **性能优化**：需要理解复杂的性能特征

### 触发方式

思考模式通过特定关键词触发，每个级别分配不同的思考预算（token 数量）：

| 关键词 | 思考预算 | 适用场景 |
|--------|---------|----------|
| `think` | 基础 | 简单的分析任务 |
| `think hard` | 中等 | 需要更深入的推理 |
| `think harder` | 较高 | 复杂的多步骤分析 |
| `ultrathink` | 最高 | 最复杂的推理任务 |

### 使用示例

```
> think hard 关于这个并发问题：多个用户同时修改同一条记录时，
  当前的乐观锁实现是否有竞态条件？

Claude 会进行深入的思考分析，考虑：
- 各种并发场景
- 时序问题
- 边界条件
- 可能的解决方案
```

```
> ultrathink 分析这个加密实现的安全性，考虑所有已知的攻击向量

Claude 会使用最大的思考预算来进行全面的安全分析。
```

## 两种模式的组合使用

在实际工作中，你可能需要组合使用两种模式：

### 场景：大型系统重构

```
# 第一步：用计划模式规划
> [Plan Mode] 规划将单体应用拆分为微服务的方案

# 第二步：用思考模式分析关键决策
> think hard 关于服务间通信，REST vs gRPC vs 消息队列，
  考虑我们的场景（高频率、低延迟、需要事件溯源）

# 第三步：批准计划后开始执行
> 按照计划开始执行第一步
```

## 何时使用哪种模式？

```
              你的任务
                │
         涉及多个文件？
         ┌──yes──┴──no──┐
         │              │
     计划模式      逻辑复杂？
    先规划再执行   ┌─yes─┴──no──┐
                  │            │
             思考模式       直接执行
           深入推理后再做   简单任务
```

### 快速参考

| 任务类型 | 推荐模式 | 示例 |
|----------|---------|------|
| 修改一个函数 | 直接执行 | "修复这个 null 检查" |
| 添加一个新功能 | 计划模式 | "添加用户权限系统" |
| 调试复杂 Bug | 思考模式 | "分析这个竞态条件" |
| 大规模重构 + 复杂逻辑 | 两者结合 | "拆分微服务" |

## 实用技巧

1. **默认使用计划模式处理大任务**：先规划再执行，减少返工
2. **对安全关键代码使用 `think hard`**：深思熟虑好过匆忙实现
3. **审查计划时提出问题**：如果计划的某个步骤不清楚，要求 Claude 解释
4. **迭代计划**：不满意的地方直接要求修改，不需要全盘否定
5. **`ultrathink` 用在刀刃上**：它消耗更多资源，留给最复杂的问题

---

## 关键要点

- **计划模式** 适合广度 —— 多文件、多步骤的任务，先规划后执行
- **思考模式** 适合深度 —— 复杂逻辑、安全分析、性能优化
- 计划模式通过 `Shift+Tab` 切换或在提示中明确要求
- 思考模式通过 `think`、`think hard`、`think harder`、`ultrathink` 关键词触发
- 两种模式可以组合使用，先规划再深度分析关键决策
- 简单任务不需要额外模式，直接执行即可
