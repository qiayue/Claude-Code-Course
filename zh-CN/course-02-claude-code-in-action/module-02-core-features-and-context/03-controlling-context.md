## 核心概念

随着对话变长，上下文窗口会逐渐填满。有效地控制上下文是高效使用 Claude Code 的关键技能。本课时将介绍会话管理、上下文压缩和记忆系统。

## 上下文窗口基础

Claude Code 有一个固定大小的上下文窗口。每条消息、每次文件读取、每次命令输出都会消耗上下文空间。当接近限制时：

- Claude 的回复质量可能下降
- 系统会自动压缩早期的对话内容
- 某些上下文可能会丢失

理解这个机制是有效管理上下文的前提。

## 会话控制命令

### `/compact` — 压缩对话

当对话变长但你还想继续当前任务时，使用 `/compact`：

```
> /compact
```

`/compact` 的工作原理：
1. 总结当前对话历史中的关键信息
2. 用简短的摘要替换详细的对话记录
3. 重新加载 `CLAUDE.md` 文件（确保指令不丢失）
4. 释放上下文空间，允许继续对话

**适用场景：**
- Claude 已经了解了当前任务的大量背景
- 你想在相同上下文中继续下一个相关任务
- 上下文快要满了但任务还没完成

你也可以带参数使用，指导压缩的重点：

```
> /compact 保留关于数据库迁移的所有信息
```

### `/clear` — 完全清除

当你要开始一个全新的、不相关的任务时：

```
> /clear
```

`/clear` 会完全清除对话历史，给你一个全新的开始。`CLAUDE.md` 和记忆文件会在新会话中重新加载。

**适用场景：**
- 切换到完全不同的任务
- 对话已经偏离主题太远
- 想要一个干净的起点

### 如何选择？

| 情况 | 推荐命令 |
|------|----------|
| 对话很长，但还在同一个任务上 | `/compact` |
| 完成了一个任务，开始另一个相关任务 | `/compact` |
| 切换到完全不同的任务 | `/clear` |
| Claude 似乎混淆了或"忘记"了什么 | `/clear` 然后重新提供关键上下文 |

## 自动记忆系统

Claude Code 有一个**自动记忆**（Auto Memory）系统，让 Claude 能够跨会话积累知识。

### 工作原理

当 Claude 在工作中发现有价值的信息时，它会自动保存笔记：

- 构建命令和调试经验
- 架构发现和代码模式
- 你的编码偏好和习惯

这些笔记保存在 `~/.claude/projects/<project>/memory/` 目录下：

```
~/.claude/projects/<project>/memory/
├── MEMORY.md          # 简洁索引，每次会话加载
├── debugging.md       # 调试模式笔记
├── api-conventions.md # API 设计决策
└── ...                # 其他主题文件
```

### MEMORY.md

`MEMORY.md` 是记忆系统的入口点：

- 每次会话开始时自动加载前 200 行
- Claude 会保持它简洁，将详细内容移到主题文件中
- 主题文件按需加载（Claude 需要时会自动读取）

### 手动记忆

你也可以直接告诉 Claude 记住某些信息：

```
> 记住：这个项目使用 pnpm，不是 npm

> 记住：API 测试需要本地 Redis 实例在运行
```

Claude 会把这些信息保存到自动记忆中。

### 管理记忆

使用 `/memory` 命令管理记忆系统：

```
> /memory
```

这会显示：
- 当前加载的所有 `CLAUDE.md` 和规则文件
- 自动记忆的开关状态
- 打开记忆文件夹的链接

你可以：
- 直接编辑记忆文件（它们是纯 Markdown）
- 删除不再需要的记忆
- 开启或关闭自动记忆功能

### 关闭自动记忆

如果你不想使用自动记忆：

在项目设置中：
```json
{
  "autoMemoryEnabled": false
}
```

或通过环境变量：
```bash
CLAUDE_CODE_DISABLE_AUTO_MEMORY=1
```

## CLAUDE.md vs 自动记忆

两个系统互补但有不同的用途：

| 特性 | CLAUDE.md | 自动记忆 |
|------|-----------|----------|
| **谁写的** | 你 | Claude |
| **包含什么** | 指令和规则 | 学习和发现 |
| **范围** | 项目/用户/组织 | 当前项目 |
| **用途** | 编码标准、工作流、架构 | 构建命令、调试经验、偏好 |

**经验法则：**
- 用 `CLAUDE.md` 写你**希望 Claude 遵循**的内容
- 让自动记忆记录 Claude **自己发现**的内容

## 上下文管理最佳实践

### 1. 保持 CLAUDE.md 精简

```markdown
# 好的实践
## 构建命令
- `npm test`：运行测试
- `npm run lint`：代码检查

# 避免的实践
## 构建命令
npm test 命令会运行所有的单元测试和集成测试。
它使用 Jest 测试框架，配置文件在 jest.config.ts 中。
如果你只想运行单个测试文件，可以用 npm test -- path/to/file...
（太多细节，不够简洁）
```

### 2. 合理拆分长对话

当你发现以下信号时，考虑压缩或清除：

- Claude 开始重复之前说过的话
- 回复变得不够精确
- 相同的文件被反复读取

### 3. 善用 `@` 引用

不要让 Claude 搜索文件，直接告诉它：

```
> 查看 @src/auth/middleware.ts 中的认证逻辑，找出安全漏洞
```

比以下更高效：

```
> 找到认证相关的文件并查看有没有安全漏洞
```

### 4. 任务上下文化

开始新任务时，提供足够的上下文：

```
> 我正在实现用户权限系统。项目使用 RBAC 模式，
  角色定义在 @src/models/role.ts 中。
  帮我为 API 路由添加权限中间件。
```

## 实用技巧

1. **`/compact` 保留关键信息**：压缩后，CLAUDE.md 完整保留
2. **`/clear` 是干净的起点**：不确定时选择 clear
3. **定期检查 `/memory`**：确保 Claude 记住的信息是准确的
4. **使用具体引用**：`@` 引用比让 Claude 搜索更省上下文
5. **信息写入 CLAUDE.md**：如果某个信息每次都需要重复告诉 Claude，把它写进 `CLAUDE.md`

---

## 关键要点

- 上下文窗口有限，需要主动管理
- `/compact` 压缩对话但保留关键信息，适合继续当前任务
- `/clear` 完全清除对话，适合开始全新任务
- 自动记忆让 Claude 跨会话积累项目知识
- `CLAUDE.md` 存指令和规则，自动记忆存学习和发现
- 善用 `@` 引用和具体的上下文可以更高效地使用有限的上下文空间
